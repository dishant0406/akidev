# Torrential source reliability research — revision-pinned primary-source review

## Scope, evidence and answer

Reviewed the shallow local clone `/tmp/akidev-torrential-research`; the research agent's independent audit used `/tmp/akidev-torrential-c4eb18d`. `git rev-parse HEAD` returned **`c4eb18d7b3c6faf1b2889a75436c03b6d04844b7`**; origin is `https://github.com/nexxeln/torrential`. All Torrential citations below are immutable links to that revision, not `main`. The workspace declares version **0.7.0** ([Cargo.toml L5–9](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/Cargo.toml#L5-L9)). This is a **static source review**, not a runtime benchmark or security audit. No downloaded code, installation scripts, builds, tests, tracker requests, searches against indexers, or playback were executed. The only additional remote dependency inspection was the LICENSE at the exact libtorrent gitlink revision.

Evidence labels used here:

- **Proved (source):** the reviewed implementation contains the mechanism. This does not assert that it works against today's upstreams or in every environment.
- **Inference:** an engineering implication of that mechanism, not an observed production result.
- **Unknown/unverified:** needs runtime, dependency, operational, licensing or content-rights verification.

**Bottom line:** Torrential does not possess a special database of guaranteed playable/correct sources. It federates known indexes, normalizes and deduplicates their observations, applies strict title/year/span heuristics and device-aware ranking, then **tries actual torrent metadata and a selected video file**, falling back when a candidate cannot start. File selection checks episode numbering/container, not wanted file title/year; it must not be mistaken for complete identity verification. Its most transferable idea is the separation of **catalog identity → release evidence → file evidence → startup evidence → sustained playback health**. Akidev can adopt those mechanisms in its existing shared Rust core and server, without replacing its anime-specific mapping, signed source definitions, debrid/CDN path, or HLS delivery.

Crucially, Torrential's attempt-level `Playing` means that a selected video file has received **any bytes** or the job is complete. Those bytes need not be new to this attempt, contiguous, or at the playable file head: the check uses total selected-file progress, after requesting the file end for probing. It is not proof of decoding, sustained throughput, complete playback, language accuracy, or correct audiovisual episode content ([`Trial::run`, `first_bytes`, attempt.rs L443–468, L561–570](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/attempt.rs#L443-L570)). A successful source response can even contain zero results; aggregate search success only requires one successful provider answer ([assemble.rs L42–53](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/assemble.rs#L42-L53)). Do not turn either event into a “correct playable episode” metric.

## 1. Architecture and complete selection pipeline

**Proved (source):**

1. `Catalog::search` asks IMDb suggestions plus Cinemeta films and series concurrently, sharing an eight-second deadline. IMDb ordering leads; duplicates merge by title ID; when any card holds all search words, cards that do not are omitted. Details come from Cinemeta, not from the torrent index ([catalog.rs L242–285](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/catalog.rs#L242-L285), [L447–491](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/catalog.rs#L447-L491)).
2. `Titles::resolve` validates the film/episode against catalog details. A series without an explicit episode selects the next aired episode from watch history. `playable` rejects nonexistent, unaired and film-as-episode requests ([titles/mod.rs L129–159](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/mod.rs#L129-L159), [L207–234](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/mod.rs#L207-L234)).
3. `Titles::query` looks up namesakes and constructs `Wanted`; `Wanted::queries` creates episode, season-pack and complete-series query variants. The torrent search is restricted to video-capable sources ([core/title.rs L328–397](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/core/src/title.rs#L328-L397), [search/lib.rs L199–245](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/lib.rs#L199-L245)).
4. `Search::search_with_progress` launches every selected `(source, query-text)` future under one query deadline. It reports intermediate merged/ranked results, but stores runs in source/query order so network completion order does not change the final merge. Source adapter panics are caught and converted to a bad-response outcome. Search itself does not start a download ([search/lib.rs L1–6](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/lib.rs#L1-L6), [L193–271](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/lib.rs#L193-L271)). Some publisher adapters fetch small metainfo for identity; that is distinct from downloading media.
5. `vet`, `merge`, `combine`, `filter`, `fitted` turn source observations into ranked releases. `rank::rank` produces the common order shown to clients and used by title attempts ([assemble.rs L34–80](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/assemble.rs#L34-L80)).
6. `attempt::run` first reuses an eligible local download, otherwise consumes search progress while trying candidates. Metadata/file/start checks, cancellation cleanup and reasoned fallback live in the daemon rather than the UI ([attempt.rs L100–210](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/attempt.rs#L100-L210)).
7. The browser receives explicit `resolved`, `searched`, `trying`, `check`, `skipped`, `playing`, `failed` events. `titleSession::attempt` keeps reading to the terminal stream outcome; an unexpectedly cut stream is an error, not successful playback ([web/player/titleSession.ts L57–134](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/web/src/player/titleSession.ts#L57-L133)).

**Inference:** the useful resilience comes from diversity of indexes plus disciplined validation and lifecycle handling, not a magic “best torrent” score or a guarantee of fresh seed counts.

## 2. Where releases actually come from

The built-in registry is explicit; no autonomous mirror discovery is present. Its authority order is Arch Linux, Ubuntu, Debian, Internet Archive, Academic Torrents, Knaben, APiBay, Nyaa. The first five are marked `lawful`; only **Internet Archive, Knaben, APiBay and Nyaa** are marked video-capable. Configured Torznab sources follow and are assumed video-capable, private and not `lawful`. Replacement endpoint URLs and disabled sources are user configuration; a title search does not automatically search Linux distributions or Academic Torrents ([sources/mod.rs L32–102](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/sources/mod.rs#L32-L102), [L288–339](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/sources/mod.rs#L288-L339), [SearchConfig L51–64](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/lib.rs#L51-L64)).

### Prowlarr / Jackett integration is discovery, not a hosted Torrential provider

`Probe::find` first asks `t=caps`. If the response is not Torznab, it recognizes Prowlarr from `api/v1/system/status`, lists enabled torrent indexers from `api/v1/indexer`, and derives each `<id>/api` URL. For Jackett it asks `api/v2.0/indexers/all/results/torznab/api?t=indexers&configured=true`, validates indexer IDs as path segments, then derives per-indexer feeds. `Probe::check` reports whether caps answer and which standard top-level categories they carry. Each request has a ten-second cap and no retry ([indexers.rs L93–180](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/indexers.rs#L93-L180), [L224–259](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/indexers.rs#L224-L259)).

**Inference:** an administrator-controlled Prowlarr instance is a practical way to add regional/private indexes without copying tracker scrapers. It does not create rights to their content, bypass their rules, or eliminate their outage/rate-limit behavior. There is no evidence that adding all configured trackers improves successful playback for Akidev's actual languages and title catalog.

## 3. Title and episode correctness: stronger than keyword search, still heuristic

### Listing relevance is only a preliminary guard

`Terms` sanitizes/lowercases query text and deduplicates tokens. Relevance counts matched words and year agreement; two/three-token concatenations accommodate joined names. A row is preliminarily relevant when it matches at least one non-stopword (or any word in an all-stopword query). `vet` fails the entire source answer as `Irrelevant` when **more than half** its rows fail that guard; otherwise it retains matching rows. This catches “latest uploads returned instead of search results,” but is deliberately looser than title identity ([terms.rs L31–109](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/terms.rs#L31-L109), [assemble.rs L34–38](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/assemble.rs#L34-L38)).

### `Wanted::fit` is the stricter gate

- Normalized title name must be exactly equal, after lowercasing, punctuation folding, selected Latin accent folding and `& → and`.
- A film's stated year may differ by **one**; a series' stated start year has **zero** slack.
- A yearless namesake release is allowed for the catalog-leading title, not for a shadowed one, with a country-coded series exception.
- Country tags must agree with catalog countries when known.
- `Span::covers` checks film, exact episode, a season, a season range, or complete series.
- `Wanted::queries` asks `name SxxExx`, country-coded variants for namesakes, `name Sxx`, and `name complete`; films ask year plus possibly a bare-name variant.

Evidence: [core/title.rs L84–123](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/core/src/title.rs#L84-L123), [L125–152](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/core/src/title.rs#L125-L152), [L352–397](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/core/src/title.rs#L352-L397).

`named`/`Reading::of` recognize SxxExx, `1x02`, episode tokens, season packs, spelled seasons, complete series, fansub `[Group] Title - 05`, revision suffixes and bounded multi-episode ranges. `read` lets the filename override surrounding folder/torrent evidence when sufficiently informative; bare numbers count as episodes only with a surrounding season or fansub grouping ([core/title.rs L35–82](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/core/src/title.rs#L35-L82), [L219–258](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/core/src/title.rs#L219-L258), [L498–565](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/core/src/title.rs#L498-L565), [L612–676](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/core/src/title.rs#L612-L676)).

### After metadata, it chooses a specific file

`stream::episode` finds the largest nonsample video whose file/folder/torrent reading is the requested `(season, episode)`; it does **not** merely choose the largest file in a season pack. A multi-episode file is playable only as its **first** episode, because the implementation lacks a boundary/time offset for subsequent episodes. Film selection uses `Plays::preferred` among nonsample videos, not a catalog-content fingerprint. `around` selects accompanying subtitle paths, narrowing to the video's stem when any subtitle carries it ([playback/stream.rs L34–69](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/playback/stream.rs#L34-L69), [L262–299](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/playback/stream.rs#L262-L299)).

**Limitations/inferences:**

- `Wanted` carries one catalog name, not a collection of official/local/romaji/English aliases. No AniList/MAL mapping or absolute-episode-to-season translation is established by this pipeline. Nyaa participation is not equivalent to anime identity support.
- Its release/filename SxxExx parser allows up to three episode digits and its bare fansub caller also uses a three-digit bound (the typed `Span` parser is separate and not subject to this bound); Akidev already handles four-digit anime episode numbers. Copying this parser wholesale risks regressions for long-running anime ([core/title.rs L612–649](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/core/src/title.rs#L612-L649), [bare fansub caller L498–546](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/core/src/title.rs#L498-L546); local Akidev `desktop/core/src/releases.rs:99–109, 196–223`).
- Exact normalized matching can reduce recall for translated titles, alternate names, unconventional filenames, specials and split cours. Catalog namesake popularity ordering is a heuristic, not identity authority.
- **The selected file is not checked against wanted title/year.** `video_of` receives metainfo, episode and playback capabilities but no wanted title/year; episode selection compares only season/episode. A correctly named listing containing `Other.Show.S01E02` therefore lacks a file-title rejection at this stage. This is a proved validation gap, not an observed malicious result ([attempt.rs L539–558](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/attempt.rs#L539-L558), [stream.rs L34–68](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/playback/stream.rs#L34-L68)). Secure adoption must reject contradictory file title/year/episode evidence and preserve unknown identity. A media probe validates structure/runtime, not semantic episode identity or dub/subtitle accuracy.
- **Search/playback disagree on multi-episode coverage.** `named` expands release ranges while playback accepts only the first episode; an E02 listing match can fail for `S01E01E02`. Listing coverage is not a verified file/time offset ([title.rs L223–235](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/core/src/title.rs#L223-L235), [stream.rs L296–299](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/playback/stream.rs#L296-L299)).
- **File-aware ranking is not necessarily wanted-file ranking.** `rank::opened` prefers a file across supplied videos without episode filtering; episode playback picks the largest requested-episode match. Codec/picture rank can describe another file. Reuse one authoritative selected-file function for both ranking and playback ([rank.rs L99–106](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/rank.rs#L99-L106), [stream.rs L62–68](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/playback/stream.rs#L62-L68)).
- The country/year/catalog checks are useful gates, but require good metadata. A stale/missing namesake catalog can alter the decision.

## 4. Merge and ranking: what “reliable” actually means

### Deduplication and provenance

`merge` groups hash identities; a hybrid observation aliases its v2 identity to v1, allowing v2/hybrid sightings to join. Locator-only rows get a stable SHA-1 of their URL as an ID; these are **not** necessarily deduplicated with later hash-identified rows. `combine` retains ordered source provenance; prefers a longer/whole title; size/date/link fields use source authority; peer counts use the maximum reported pair; flags union across sightings; public tracker sets are deduplicated and capped at 32. It does not average seed counts or treat multiple sources as independent confidence votes ([assemble.rs L173–290](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/assemble.rs#L173-L290)).

Private `.torrent` links, info pages and tracker passkeys are removed from **shown** releases but retained in the engine's download context. When public and private sightings join, only public trackers are shared. Saved Torznab links remove API-key-valued query parameters and add the currently configured key on resolution; links with keys elsewhere are not safely persisted ([assemble.rs L155–168, L226–246](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/assemble.rs#L155-L246), [torznab.rs L40–73](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/sources/torznab.rs#L40-L73)).

### Hard exclusion versus soft preference

For a wanted title, `fitted` rejects extras, wrong title/span, known zero-seeder nonlawful releases, and a computed bitrate below **0.25 Mbit/s**. This is a “likely fake” heuristic, not forensic detection. Unknown bitrate/size is accepted. `max_size`/`min_seeds` explicit query filters require known values, whereas device/profile fit generally treats unknown values as fitting ([assemble.rs L292–337](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/assemble.rs#L292-L337), [rank.rs L18–65](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/rank.rs#L18-L65)).

Swarm tier is **Strong ≥20**, **Fair 5–19**, **Weak 1–4**. Missing seeders on a `lawful` catalog are Strong; explicit zero on a lawful catalog or unknown on other indexes is Unknown; explicit zero elsewhere excludes the release. The “lawful missing count ⇒ strong” rule assumes HTTP web seeds, rather than observing that the seed is currently available ([rank.rs L21–32](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/rank.rs#L21-L32)).

`PlayRank` is **lexicographic**, not a weighted confidence formula. For title search it compares:

1. non-CAM;
2. fits disk/preferences/playback/bitrate cap;
3. not marked only in a foreign language;
4. swarm tier;
5. stated year where namesakes need it;
6. official/lawful standing;
7. bitrate in the resolution's comfortable band;
8. fewer unexplained extra words;
9. narrower span (episode before season before complete);
10. hardware/software/no decoding rank;
11. modern container;
12. resolution closeness and actual picture size when enriched;
13. reported seeders.

The normal-search tie chain then uses requested sort, relevance, fit, standing, screen, architecture/language, seeders, fewer extra words, downloads, newer-looking name, and stable release ID ([rank.rs L207–300](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/rank.rs#L207-L300)). Thus “lawful first” does **not** mean before all better-fit/language/swarm evidence. `Flag::Trusted` is collected from Nyaa/APiBay but `standing` rewards **Official and lawful**, not that flag. There is no demonstrated uploader reputation learning, historical success model, malware scanning, or measured throughput ranking in this function.

The bitrate bands are SD 0.3–4, 720p 0.6–8, 1080p 1–16, 2160p 3–40 Mbit/s. Browser caps derive from the screen's upper band; external players do not get that cap. Unknown codecs default to assumed H.264 for decoding rank. “Original” language is modeled as unmarked or English, not the catalog's original language ([rank.rs L34–76](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/rank.rs#L34-L76), [L112–136](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/rank.rs#L112-L136), [L179–205](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/rank.rs#L179-L205)). **Do not transplant the English assumption into anime or multilingual Indian catalog selection.**

## 5. Actual attempts, torrent lifecycle and playback recovery

### Bounded startup with reasoned fallback

Defaults: metadata/file-list wait **20 seconds**, first-video-byte wait **30 seconds**, overall play budget **180 seconds**. The line considers the top **12** ranked candidates, reuses suitable existing downloads, and moves releases that failed within **six hours** to the back. Failures are in memory and reset on process restart; this is not a persisted health score or a provider circuit breaker ([titles/mod.rs L28–68](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/mod.rs#L28-L68), [L82–127](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/mod.rs#L82-L127)).

An attempt tries at most **six** candidates. Two following magnet candidates have metadata look-ahead; `.torrent` links are not eagerly grabbed. It can start early with a strong lawful source; another strong source can start after **2.5 seconds**; weaker candidates wait for the search to end. Slower indexes continue feeding the line during trials. This trades latency against later better answers, not “always wait for every provider” ([attempt.rs L29–40](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/attempt.rs#L29-L40), [L223–231](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/attempt.rs#L223-L231), [L284–315](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/attempt.rs#L284-L315), [L369–375](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/attempt.rs#L369-L375)).

Each `Trial` obtains metadata from an existing job, cached metainfo, fetched torrent URL or magnet peers; selects a video by episode numbering or film preference and checks its container, without wanted file-title/year validation; selects that video plus subtitles; starts via the owner; requests the file end for probing; polls first-byte progress every 100 ms. File-list timeout, no video, incompatible container, too large/disk full, no data and generic failures remain distinct `Skip` reasons ([attempt.rs L384–468](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/attempt.rs#L384-L468), [L486–570](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/attempt.rs#L486-L570)).

`Hold` ownership is acquired before requesting download work. On failed/cancelled trials it is released explicitly or by `Drop`, allowing the owner to restore/clean up work rather than leaking failed downloads. A stalled source is paused **after** its replacement starts; an explicitly pinned source disables alternative selection ([attempt.rs L317–366](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/attempt.rs#L317-L366), [L470–483](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/titles/attempt.rs#L470-L483)).

### Range-aware streaming rather than reading sparse-file holes

The daemon serves byte ranges and waits on `want_range` before reading incomplete files from disk. Requests seek to verified/written bytes; cancellation/seek closes the old read. Its wait loop polls every 100 ms and has a five-minute stall timeout. The native shim's `Written` checks both piece hash bitfields and pending write queues, so a verified-but-not-written piece is not yet safe to read ([http.rs L802–905](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/http.rs#L802-L905), [shim.cpp L157–176](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/engine/cpp/shim.cpp#L157-L176)). Torrent hash checks establish bytes match the torrent, **not** that the torrent is the correct episode or safe media.

Other downloads trickle at 64 KiB/s when any watched stream has under 60 seconds of contiguous lead; they return to free throughput above 120 seconds, with hysteresis between the thresholds. Actual readers matter, not merely a cast lease. This is a useful backpressure pattern ([owner/streams.rs L15–34](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/owner/streams.rs#L15-L34), [L132–178](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/owner/streams.rs#L132-L178)). `stream::start` estimates buffering from runtime, current rate discounted to 90%, and ten seconds of head buffer; that forecast cannot guarantee a changing swarm will stay fast ([playback/stream.rs L12–16, L83–94](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/playback/stream.rs#L12-L94)).

The engine retains redundant peer connections after metadata to avoid a 60-second reconnect delay, permits more web-seed connections, reduces web-seed request chunks to 1 MiB and peer request queue time to one second. These are libtorrent-specific streaming tunings, not settings that can be assumed to exist in Akidev's engine ([shim.cpp L286–309](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/engine/cpp/shim.cpp#L286-L309)).

### Internet Archive web-seed repair is a concrete distinctive mechanism

Redirected multi-file web seeds can become per-file seeds in libtorrent, leaving a piece spanning two files without a complete source. Torrential asks Archive metadata for the item's two servers/directories and adds parent-root web seeds that serve the full torrent layout. A lookup begun with the `.torrent` fetch is shared for up to 60 seconds, at most eight held lookups. For other torrents, it follows a first-byte request and derives a root **only if** the redirect preserves the complete file path and is not a signed query link ([web_seeds.rs L24–48](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/web_seeds.rs#L24-L48), [archive_org.rs L335–415](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/sources/archive_org.rs#L335-L415), [redirect.rs L42–93](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/redirect.rs#L42-L93), [search/lib.rs L135–145](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/lib.rs#L135-L145)).

**Inference:** worth testing with lawful multi-file Archive fixtures if Akidev's torrent library has the same redirect behavior. It is not a universal CDN discovery mechanism; do not synthesize roots for signed or renamed resources.

### Conversion, mid-playback recovery and disk lifecycle

Torrential invokes ffprobe over its own stream and builds ffmpeg argv vectors (not a shell). Browser-compatible video is copied; AAC copied, other audio becomes stereo AAC; unsupported video becomes H.264 (VideoToolbox on macOS or x264), bounded to 1080p. Output is a fragmented MP4 stream; pacing is enabled for supported ffmpeg versions ([media/ffmpeg.rs L47–128](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/media/ffmpeg.rs#L47-L128)). **Do not replace Akidev's established HLS/iOS-range-compatible delivery with this simply because the startup selection is attractive.**

The browser recovery reducer requires waiting, less than one second buffered and no incoming bytes for **45 seconds**, or a download error, to switch. It keeps the old source while finding another and becomes exhausted rather than endlessly switching; incoming bytes can restore normal state. Timestamp-preserving recovery cannot guarantee alignment between cuts/editions ([recovery.ts L3–70](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/web/src/player/recovery.ts#L3-L70)).

Automatic plays use a dedicated owned folder, pause after ten minutes without streams, and evict least-recently-watched plays when over the default 20 GiB policy. Busy, latest-watched, user-kept and saved-title plays are protected; the budget is therefore not a hard ceiling on all retained data. The owner rechecks protected state before deletion and waits for engine release; do not reduce this to “delete oldest filename” ([owner/plays.rs L1–76](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/owner/plays.rs#L1-L76), [L338–511](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/owner/plays.rs#L338-L511), [README L76–80](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/README.md#L76-L80)).

## 7. Security, privacy and “do not copy” boundaries

These findings identify controls and residual risks. No insecure input-handling code was copied or modified; adoption must implement the secure alternative first.

### Useful controls proved in source

- Config search structs reject unknown fields; configured-source names/duplicates and http(s) endpoint schemes are validated ([lib.rs L51–85](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/lib.rs#L51-L85), [sources/mod.rs L288–339](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/sources/mod.rs#L288-L339)).
- Picture fetches allow known HTTPS domain families on standard port, no credentials, check redirects and resolve only public addresses; accept JPEG/PNG/WebP signatures rather than arbitrary HTML/SVG ([catalog.rs L154–196](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/catalog.rs#L154-L196), [http.rs L190–235](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/http.rs#L190-L235)). Signature checks are not full safe-image decoding.
- Network devices use random 32-byte bearer tokens with SHA-256 keys in storage; pairing expires in ten minutes, burns after five wrong codes, and rate-limits tries/misses. Cast grants address one torrent/file; devices cannot add/remove pairings ([devices/mod.rs L23–113](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/devices/mod.rs#L23-L113), [web/devices.rs L106–134](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/web/devices.rs#L106-L134)).
- HTTP guards check Host/Origin/Fetch-Site and device/local identity before dispatch; state-changing web routes use JSON POST, not GET. Header/body sizes are bounded. Loopback web requests are privileged after origin checks; this is a local-machine trust model, **not per-user tenant authorization** ([http.rs L988–1080](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/http.rs#L988-L1080), [web/mod.rs L1–6](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/web/mod.rs#L1-L6), [http.rs L31–66](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/http.rs#L31-L66)).
- A torrent's name and file paths reject slash traversal/absolute/empty components before disk use ([metainfo.rs L24–37](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/metainfo.rs#L24-L37)).

### Risks and secure adoption requirements

1. **SSRF / CWE-918:** `Search::fetch_torrent` accepts any http(s) URL then uses the ordinary HTTP client, not the public-only client. The web API's `target` permits a remote `.torrent` URL. Torznab-returned/public-index URLs are also upstream-controlled. Redirect-root lookup uses public DNS resolution and checks redirect IPs, but its initial request constructor accepts arbitrary http(s) seeds; private literal initial destinations are not visibly denied there. Archive metadata server names get syntax checks, not a reviewed destination allowlist. These are exposed fetch surfaces, unlike an administrator-pinned internal Prowlarr endpoint, which is legitimate infrastructure ([lib.rs L306–323](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/lib.rs#L306-L323), [web/mod.rs L262–275](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/web/mod.rs#L262-L275), [http.rs L56–79](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/http.rs#L56-L79), [redirect.rs L21–48](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/redirect.rs#L21-L48), [archive_org.rs L398–415](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/search/src/sources/archive_org.rs#L398-L415)). **Secure fix:** separate admin-pinned internal integrations from user/upstream-controlled destinations; allowlist expected external origins, enforce public IPs on initial and every redirect/connection, block private/link-local/metadata/mapped/reserved addresses, constrain schemes/ports/credentials, prevent DNS rebinding and proxy bypass, and bound requests. Do not claim its picture protection secures all torrent/seed fetches.
2. **Transport exposure / CWE-319:** LAN pairing and streams use HTTP by default and cookie `Secure` is conditional on configured public HTTPS. Tokens over a hostile LAN can be intercepted. Network device access is broad over one owner's state. **Secure fix:** HTTPS or an explicitly trusted encrypted overlay for remote use, secure cookies, CSRF controls, least-privilege grants, object ownership checks on every sensitive web action and account/tenant separation for a hosted Akidev API ([devices/mod.rs L219–241](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/devices/mod.rs#L219-L241), [web/devices.rs L33–38](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/web/devices.rs#L33-L38)).
3. **Validation / CWE-20 and disclosure / CWE-209:** some API request structs (e.g. `Refs`, `Ref`, `Pair`) do not declare `deny_unknown_fields`; `body` returns detailed serde errors, and generic `fail` returns the whole core error. Not equivalent to strict schemas and generic public errors ([web/mod.rs L212–241, L297–299](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/web/mod.rs#L212-L299), [web/devices.rs L60–69](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/web/devices.rs#L60-L69)). **Secure fix:** typed bounded schemas, reject unknown fields/duplicate parameters, generic user errors, private sanitized diagnostics. Caps on total body size do not replace field bounds.
4. **Filesystem / CWE-22, CWE-59:** lexical slash rejection is useful but not a complete portable policy for backslashes, Windows drive/UNC paths, symlinks, races, special files and torrent-library path rewriting. Its owner/deleter machinery adds identity-based protection; copy the invariant, not only the short `Metainfo::new` check. **Secure fix:** platform-aware normalization, reject symlink/special-file entries, trusted owned roots, no-follow/descriptor-relative safe filesystem operations and concurrency tests ([metainfo.rs L24–37](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/metainfo.rs#L24-L37), [owner/plays.rs L293–336](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/owner/plays.rs#L293-L336)).
5. **Resource exhaustion / CWE-400:** finite startup waits, response caps and result limits are good, but do not justify copying unbounded all-source/all-query fanout or concurrent work into a public multiuser backend. Hedge only idempotent inexpensive reads; honor upstream quotas/429/retry policy; bound per-tenant queries, metadata probes, decode/transcode CPU, disk and queue counts.
6. **Privacy / CWE-200:** no-upload is not anonymity. Search terms reach catalogs/indexers; torrent participation exposes the engine's IP/hash requests to peers/trackers/DHT; metadata look-ahead also contacts swarms. Browser-like User-Agent does not hide IP or search interest. Local watch/download/device state is retained, and device storage includes `seen_from` ([devices/mod.rs L299–320](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/devices/mod.rs#L299-L320)). Protect history, minimize logs, redact API keys/passkeys/URLs, provide retention controls and accurate notices.
7. **Downloaded executables / supply chain:** ffmpeg builds are pinned to URL, size and SHA-256 and fetched on first conversion; they are not merely “included MIT tools.” Updates download GitHub release assets, test-run and replace an executable with a folder lock; a checksum alone is not proof against a compromised release publisher. **Secure fix:** maintain explicit dependencies/build provenance, signatures/attestations where available, platform verification, least-privileged processes, explicit update policy and current security maintenance. Never copy curl-pipe-shell installation as an application security requirement ([ffmpeg/fetch.rs L21–108](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/ffmpeg/fetch.rs#L21-L108), [update/release.rs L172–208](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/update/release.rs#L172-L208)). This review did not execute or verify those assets.

### No-upload policy: implementation fact, not rights/privacy assurance

The daemon selects `UploadPolicy::Off`; the shim sets zero unchoke slots/fast set and registers `NoUpload`, whose peer plugin chokes/refuses piece requests. Local peers are put in the global peer class so limits apply there too ([libtorrent.rs L581–602](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/libtorrent.rs#L581-L602), [shim.cpp L236–260](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/engine/cpp/shim.cpp#L236-L260), [L313–330](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/engine/cpp/shim.cpp#L313-L330)). This is piece-upload prevention, not “no network traffic sent.” Private trackers may impose ratio/seeding requirements; do not promise compatibility. VPN interface binding covers torrent peers/trackers/DHT and disables local discovery when bound; it is Unix-only and does not prove all catalog/search/ffmpeg/update HTTP uses that interface ([libtorrent.rs L581–638](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/crates/daemon/src/daemon/libtorrent.rs#L581-L638), [README L159–166](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/README.md#L159-L166)).

For Akidev, make verified licensed/public-domain/user-authorized media the evaluation and adoption baseline; retain rights provenance separately from availability/rank.

### Deployment assumptions

Torrential is an owner-operated background engine exposing a bundled browser application to that computer's paired devices. Server installation boot-starts/network-listens; Docker uses **host networking** for address naming and TV SSDP, runs as UID/GID 1000 by default, persists config/state/downloads under `/data`, and uses a Debian runtime for fetched ffmpeg's glibc needs. Tailscale or a Caddy HTTPS reverse proxy is recommended for away-from-home access. This is not the same threat/scale model as an anonymous public shared streaming API ([README L41–68](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/README.md#L41-L68), [Dockerfile L13–38](https://github.com/nexxeln/torrential/blob/c4eb18d7b3c6faf1b2889a75436c03b6d04844b7/Dockerfile#L13-L38)). Host networking, automatic login/boot install and broad owner-device privileges should not be copied merely to improve Akidev search.

## 10. Concrete Akidev transfer plan (recommendations, not implementation claims)

### Deployment and existing fit in this workspace

Akidev's deployment path is GitHub Actions to Docker Compose, with frontend/API containers on the stated domains (`.github/workflows/deploy.yml`, `docker-compose.yml`, root `README.md:7–25`). Deploy the website's shared-core changes with the API/server image and the site's contract changes with the frontend; desktop changes require a new desktop release. Signed `sources.json` updates are a separate channel and can change live indexers without a code deploy: the repository's embedded document is version 10, but the live published feed was not fetched for this static review. The explicit unknown-seeder behavior and Archive.org fallback are local engine bugs unaffected by adding a new indexer. Verify live definitions and current server logs/telemetry before estimating affected traffic; no current production measurement is claimed.

Akidev already has one shared core behind desktop and website/server, not two independent search implementations: local `README.md:18–25`. `desktop/core/src/sources.rs:1–8, 19–35, 77–118` embeds signed data definitions, verifies schema/version/signature and bounds them; keep this instead of replacing it with a static provider registry. `desktop/core/src/indexers/mod.rs:25–45, 87–110` already has ten-minute answer caching, capped 24-request fanout, a 700 ms grace and one-second mirror hedge. `desktop/core/src/releases.rs:99–109, 196–238` has anime-aware four-digit/Chinese episode tokens and series season handling; retain those capabilities. `README.md:100–128` describes direct/copy/audio-only/re-encode and HLS/iOS delivery. These are local source observations at review time, **not** an immutable Akidev revision audit and not proof all proposed mechanisms are currently missing.

### Acceptance sequence for the changes

No production implementation was made. After explicit approval of the target and scope, land one separately measurable increment at a time: (1) regression corpus and attempt/source telemetry baseline; (2) fail-closed Archive.org and honest unknown-health semantics; (3) merged observations and stronger identity/file parsing; (4) profile-aware order, failure memory and progressive attempts; (5) only then metainfo/web-seed and live-scrape experiments. Keep committed regression fixtures for wrong season, bonus, short clip, same-name remake, four-digit anime, underscored files, unknown/zero seeders and mixed-source duplicates. Run `cargo test -p akidev-core`, `cargo test -p akidev-server`, format/clippy, and frontend type/lint/build for affected contracts. Then test native and deployed-web user paths against actual bytes plus ffprobe, not merely `available: true`. Run `git diff --check` on each documentation-only step; there is no production implementation to test in this review.

### Research verification record

Pinned upstream HEAD and local Akidev HEAD (`99c99c65c5e5701c68ff70588c15f90149a051d8`) were recorded. Independent bounded reviewers checked provider count, cache TTL, standing/ranking, selected-file identity, multi-episode behavior, first-byte semantics, URL controls and MIT wording. ### Validation required before a rollout claim

Use an authorized/public-domain/owned evaluation corpus with known truth: title ID, aliases, season/episode or absolute number, expected edition/dub/sub, filename layout and media runtime. Include long-running anime (four-digit episodes), sequel/year collisions, identical-title remakes, regional names, season/complete packs, extras, multi-episode files, zero/unknown/stale seed counts, partial providers, quota responses and media incompatibility.

Measure independently: provider response rate; candidate recall; false-positive title/episode rate; metadata acquisition; correct selected file; probe/decode; first-frame latency; time-to-stable-play; stalls/minute; cancellation leaks; disk/CPU/bandwidth; retry load; and SSRF/auth/path boundary failures. Compare existing Akidev behavior against one transferred mechanism at a time. A failure to find content is preferable to silently playing a different episode. Security regression tests must precede enabling any new external fetch/play surface.
